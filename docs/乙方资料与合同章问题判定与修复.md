# 乙方资料填不进去、合同章生成失效 — 判定与修复

## 一、乙方资料填不进去

### 可能原因

1. **订单交付方未进合同**  
   合同乙方来自 `salesOrder.getDeliveryParty()`。若生成合同时订单里 `deliveryParty` 为空或被覆盖，合同里乙方名称和后续用「交付方」查到的合作方详情都会空。  
   - 已做：PUT 订单时不再用 `logistics[0]` 覆盖顶层 `deliveryParty`；前端生成合同前把 `deliveryParty` 同步到 `logistics[0]`。

2. **合作管理里「用户信息维护」查不到**  
   乙方详情（地址、开户行、税号、电话）来自 **PartnerInfo**，用 `partnerInfoRepository.findByTitle(deliveryParty)` 精确匹配。  
   - 若合作方录入的 **title** 与订单里的交付方**不完全一致**（多空格、前后空格、全角/半角等），就查不到，合同里乙方资料为空。

3. **生成文档前合同实体里乙方仍为空**  
   若前面某步导致 `contract.partyBName` 仍为空，占位符会替换成空；生成前会调 `ensureContractPartyBFromSalesOrder` 从订单回填乙方并再查 PartnerInfo，但若订单无交付方或合作方仍匹配不到，合同里还是空。

### 已做修复

- **PartnerInfo 按「trim 后一致」再查一次**  
  - 新增：`PartnerInfoRepository.findOneByTitleTrimmed(String title)`，用 SQL `TRIM(title) = TRIM(?)` 查询。  
  - 在 **ContractService** 里：  
    - 创建合同时先按 `findByTitle(deliveryPartyTrimmed)` / `findByTitle(salesOrder.getDeliveryParty())` 查乙方；  
    - 若仍为 null，再调用 `findOneByTitleTrimmed(deliveryPartyTrimmed)`。  
  - 在 **ensureContractPartyBFromSalesOrder** 里：  
    - 从订单回填乙方名称后，同样先 `findByTitle`，再 `findOneByTitleTrimmed` 补全乙方详情。  

这样只要「合作管理」里录入的 title 与订单交付方在**去掉首尾空格后一致**，就能查到并填进合同。

### 你需要检查的

- 指派/生成合同时，**交付方**是否已选且已保存到订单（列表或详情里能看到 deliveryParty）。  
- **合作管理 → 用户信息维护** 里，是否有与交付方**完全一致**（或至少 trim 后一致）的「抬头」；没有则补一条。  
- 后台日志：若出现「PartyB PartnerInfo NOT found for title: xxx」或「ensureContractPartyB 合作管理中未找到」，说明仍是匹配不到，需核对 title 与交付方是否一致。

## 二、合同章生成失效

### 可能原因

1. **合同里甲方/乙方名称为空**  
   印章插入逻辑要求：  
   - 甲方章：段落里包含 `${partyASeal}` 且 `placeholders.get("${partyAName}")` 非空；  
   - 乙方章：段落里包含 `${partyBSeal}` 且 `placeholders.get("${partyBName}")` 非空。  
   若 `partyAName` / `partyBName` 为空（例如乙方未填进去），则**不会插入**对应章，并打 err 日志「甲方章/乙方章未插入: partyAName/partyBName 为空」。

2. **Word 模板里占位符被拆成多个 run**  
   Word 常把一段文字拆成多个 run（如 `${party` 和 `ASeal}` 在两个 run）。  
   原逻辑只在「某个 run 的整段文字包含 `${partyASeal}`」时才插入印章；若占位符跨 run，就永远匹配不到，章不会插。

3. **模板里没有对应占位符**  
   只有模板里写了 **`${partyASeal}`** / **`${partyBSeal}`** 才会被替换成印章。若模板用的是「甲方盖章」等文字或别的占位符，当前代码不会处理，看起来就像「章没生成」。

4. **印章图片生成异常**  
   `SealService.generateSeal(companyName)` 若抛错（例如服务器无中文字体「宋体」、或图片写入失败），会 catch 后只打日志，文档里不会出现章。

### 已做修复

- **占位符跨多个 run 时也能插章**  
  - 在 **DocumentService.replacePlaceholderWithSeal** 中：  
    - 先看整段 `paragraph.getText()` 是否包含 `${partyASeal}` / `${partyBSeal}`；  
    - 若有，先尝试在某个 run 里整段替换并插入印章（原逻辑）；  
    - 若**没有任何一个 run** 单独包含该占位符，则视为「占位符跨 run」：用整段文本截掉占位符，拆成「前文 + 印章 run + 后文」，清空原 runs 后重新组段落并插入印章图片。  
  - 这样无论 Word 如何拆 run，只要段落整体包含 `${partyASeal}` / `${partyBSeal}`，都会插章。

- **印章异常时日志更明确**  
  - catch 到异常时打印：`[DocumentService] 合同章生成失败 companyName=xxx placeholder=xxx: 异常信息`，便于排查字体、权限等问题。

### 你需要检查的

- 合同模板里是否包含 **`${partyASeal}`**、**`${partyBSeal}`**（建议直接复制，避免全角/拼写错误）。  
- 后台日志：  
  - 若出现「甲方章/乙方章未插入: partyAName/partyBName 为空」→ 先解决乙方/甲方资料是否填进去；  
  - 若出现「合同章生成失败 companyName=...」→ 看后面异常信息（常见为字体或 IO 问题）。  
- 服务器是否有**宋体**等 SealService 使用的中文字体，否则印章生成可能报错。

## 三、修改文件一览

| 文件 | 修改内容 |
|------|----------|
| `PartnerInfoRepository.java` | 新增 `findOneByTitleTrimmed(String title)`，按 TRIM(title) 匹配 |
| `ContractService.java` | 创建合同、ensureContractPartyB 时增加 trim 查询兜底 |
| `DocumentService.java` | replacePlaceholderWithSeal：支持占位符跨 run 时插入印章；印章异常时打印明确日志 |

按上述修改后，乙方资料应能在「交付方正确 + 合作方 title 一致或 trim 一致」时填进合同；合同章应在「模板含 ${partyASeal}/${partyBSeal} + 甲方/乙方名称非空 + 印章生成不抛错」时正常生成。若仍有问题，以后台日志中的「PartyB PartnerInfo NOT found」「甲方章/乙方章未插入」「合同章生成失败」为线索继续排查即可。
