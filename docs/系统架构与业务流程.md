## 二、认证与权限流程

### 2.1 登录认证流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant F as 前端
    participant A as AuthController
    participant AM as AuthenticationManager
    participant JWT as JwtTokenUtil
    participant DB as UserRepository

    U->>F: 输入用户名/密码
    F->>A: POST /api/auth/login
    A->>AM: authenticate(username, password)
    AM->>DB: loadUserByUsername
    DB-->>AM: UserDetails
    AM-->>A: 认证成功
    A->>JWT: generateToken(userDetails)
    JWT-->>A: JWT 字符串
    A->>DB: 查询 User(realName, companyTitle)
    A-->>F: { token, username, realName, ... }
    F->>F: localStorage.setItem('token', token)
    F->>U: 跳转首页/仪表盘
```

### 2.2 请求鉴权流程

```mermaid
flowchart LR
    A[前端请求带 Authorization: Bearer &lt;token&gt;] --> B[JwtRequestFilter]
    B --> C{Token 有效?}
    C -->|是| D[设置 SecurityContext]
    C -->|否| E[401 未授权]
    D --> F[Controller 执行业务]
    F --> G[返回数据]
```

### 2.3 权限规则摘要

- **放行接口**：`/api/auth/login`、`/api/auth/register`、`/uploads/**`、`/api/files/**`、`/api/upload`、`/api/debug/**`、`/api/barcode/**`
- **其余接口**：需携带有效 JWT，否则 401
- **业务数据权限**：
  - 销售订单/合同：管理员看全部；普通用户仅看「自己创建」或「被指派给自己」的订单
  - 采购订单：管理员看全部；普通用户仅看自己创建的采购单

### 3.2 销售订单状态流转

销售订单状态包括：**待指派 → 待确认订单 → 待合同盖章 → 已发货 → 已到货 → 已开票 → 已支付 → 平台已支付**，以及 **已取消**、**已退回**、**已对账** 等。

```mermaid
stateDiagram-v2
    [*] --> 待指派: 新建订单
    待指派 --> 待确认订单: 指派给交付方
    待指派 --> 已取消: 取消
    待确认订单 --> 待合同盖章: 交付方确认
    待确认订单 --> 已退回: 退回(工业电商)
    已退回 --> 待指派: 重新指派
    待合同盖章 --> 已发货: 合同盖章完成并发货
    已发货 --> 已到货: 客户签收
    已到货 --> 已对账: 生成对账单
    已对账 --> 已开票: 对账单开票
    已开票 --> 已支付: 客户付款
    已支付 --> 平台已支付: 平台回款
    平台已支付 --> [*]
```

### 3.4 对账单与结算单流程

对账单状态：**DRAFT → PENDING(待确认) → CONFIRMED → APPLIED(待开票) → INVOICED(已开票) → SETTLED(已结算)**  
结算单状态：**DRAFT → PENDING → SETTLED**

```mermaid
flowchart LR
    subgraph 对账单
        I1[DRAFT] --> I2[PENDING]
        I2 --> I3[CONFIRMED]
        I3 --> I4[APPLIED]
        I4 --> I5[INVOICED]
    end

    subgraph 结算单
        S1[DRAFT] --> S2[PENDING]
        S2 --> S3[SETTLED]
    end

    I5 --> |生成结算单| S1
    S3 --> I6[SETTLED]
```

- **对账单**：由多笔销售订单汇总生成（InvoiceService），订单状态会更新为「已对账」。
- **结算单**：由状态为「已开票」的对账单生成（SettlementService），生成后对账单状态更新为 SETTLED。

### 3.5 合同管理流程

```mermaid
flowchart TB
    A[合同列表/创建] --> B[关联销售订单]
    B --> C[选择合同模板]
    C --> D[填写甲方/乙方/金额等]
    D --> E[生成 PDF / 电子签章]
    E --> F[上传合同文件]
    F --> G[合同状态: 草稿→生效等]
    G --> H[同步到销售订单: 待合同盖章→已发货]
```

合同与销售订单通过 `sales_order_id` 或业务关联；合同盖章完成后，销售订单可进入「已发货」等后续状态。

### 3.6 采购订单流程

```mermaid
flowchart LR
    A[创建采购订单] --> B[关联销售订单/OMS订单号]
    B --> C[状态: 待确认]
    C --> D[确认/执行采购]
    D --> E[付款状态/对账状态维护]
    E --> F[完成]
```

- 采购订单与销售订单通过 `omsOrderNo` 等字段关联，用于「以销定采」场景。
- 权限：非管理员仅能查看/操作自己创建的采购订单。

### 3.7 物流与发货

```mermaid
flowchart LR
    A[销售订单 待合同盖章/已发货] --> B[维护 OrderShipment]
    B --> C[物流公司/运单号/签收时间]
    C --> D[可选: 快递100 物流轨迹]
    D --> E[更新销售订单: 已发货/已到货]
```

- **OrderShipment**：按销售订单维度存储发货信息（物流公司、单号、签收时间、送货单/签收单/箱唛 URL 等）。
- 销售订单上的物流、签收等字段可由 OrderShipment 回写更新。

## 五、经验分享可强调的点

1. **前后端分离**：前端 Vite 开发态代理 `/api` 到后端 8080，生产可 Nginx 反向代理。
2. **无状态认证**：JWT + Spring Security 过滤链，便于水平扩展。
3. **数据权限**：在 Service 层按当前用户角色与「创建人/指派人」过滤，保证订单与合同数据隔离。
4. **订单号规则**：工业电商销售订单号 = (D?) + 日期 + 姓名首字母 + 流水号，便于追溯与排重。
5. **状态机清晰**：销售订单、对账单、结算单、合同均有明确状态流转，便于对业务方讲解和后续扩展（如工作流引擎）。
6. **文档与扩展**：合同 PDF、电子签章、Excel 导出、条码等集中在独立 Service，便于维护和替换实现。
