# 顺丰对接 — 一次配成功步骤

按下面顺序做，争取一次把顺丰路由查询打通。

---

## 第一步：拿到顺丰开放平台参数

1. 登录 [顺丰开放平台](https://open.sf-express.com)（或丰桥）。
2. 在控制台里找到「路由查询」相关接口（如 **EXP_RECE_SEARCH_ROUTES**），拿到：
   - **partnerID / 顾客编码**（即 AppKey）
   - **AppSecret**（沙箱/测试与生产可能不同）
   - **API 地址**（如 `https://sfapi.sf-express.com/std/service`，沙箱可能不同）
3. 记下是**沙箱**还是**生产**，后面配置要一致。

---

## 第二步：在项目里配置顺丰参数

用 **application.yml** 覆盖默认值（推荐，便于区分环境）：

在 `oms-backend/src/main/resources/application.yml` 里增加（没有就新建对应块）：

```yaml
kuaidi100:
  # 顺丰：顾客编码(AppKey)、沙箱/生产密钥、API 地址
  sf-app-key: 你的partnerID或AppKey
  sf-app-secret: 你的沙箱AppSecret
  # 若用生产环境，再配下面并设 use-sf-prod: true
  # sf-prod-app-secret: 你的生产AppSecret
  sf-api-url: https://sfapi.sf-express.com/std/service
  use-sf-prod: false
  enable-mock: false
```

**说明：**

- 当前代码里已有默认值（见 `KuaiDi100Config.java`），若你用自己的账号，用上面配置覆盖即可。
- `sf-app-key` 对应配置类里的 `sfAppKey`，`sf-app-secret` 对应 `sfAppSecret`，`sf-api-url` 对应 `sfApiUrl`。
- 沙箱与生产的 **AppSecret / 接口地址** 可能不同，务必与开放平台一致。

---

## 第三步：确认「收件人手机号后四位」必传

顺丰路由查询**必须**传 **checkPhoneNo**（收件人手机号后四位），否则会报 **A1001 必传参数不可为空**。

系统已做两件事：

1. **前端**：从订单的「收货人电话」取后四位，请求时自动带 `checkPhoneNo`。
2. **后端**：若请求没带 `checkPhoneNo`，会按运单号查订单，用订单上的收货人电话后四位补全。

所以只要**订单上有正确的收货人电话**，一般不需要再手动传。

---

## 第四步：保证测试订单有收货人电话

用单号 **SF5122068084664**、电话 **13262568805**（后四位 **8805**）为例：

1. 打开 **销售管理 → 订单**，找到要用作测试的那条订单（或新建一条）。
2. **编辑订单**，在「物流信息」或「收货人」里填：
   - **收货人电话**：`13262568805`
   - 保存。
3. 若该订单还没发货信息：
   - 点 **操作 → 发货**；
   - **物流公司** 选 **顺丰速运**；
   - **物流单号** 填 **SF5122068084664**；
   - 保存。
4. 若已有发货信息但单号不是 SF5122068084664，可编辑该订单/发货信息，把单号改成 **SF5122068084664**，并确保收货人电话为 **13262568805**。

---

## 第五步：在页面上查一次顺丰轨迹

1. **启动后端**：`cd oms-backend` → `mvn spring-boot:run`，看到 8080 启动成功。
2. **启动前端**：`cd oms-frontend` → `npm run dev`，看到 `http://localhost:3000`。
3. 浏览器打开 **http://localhost:3000**，登录。
4. 进入 **销售管理 → 订单**；若没有「物流单号」列，在列设置里勾选 **物流单号**。
5. 找到 **物流单号** 为 **SF5122068084664** 的那一行，点击蓝色单号链接。
6. 弹出 **「快递物流信息」**，应自动请求：
   - `company=顺丰速运`
   - `trackingNumber=SF5122068084664`
   - `checkPhoneNo=8805`
7. 若返回成功，会看到物流轨迹列表；可点 **刷新** 再拉一次。

---

## 第六步：自检与常见问题

| 现象 | 处理 |
|------|------|
| **A1001 必传参数不可为空** | 确认该订单已填**收货人电话**（如 13262568805），保存后再点物流单号；F12 看请求 URL 是否带 `checkPhoneNo=8805`。 |
| **顺丰API 签名/鉴权失败** | 核对 application.yml 里 `sf-app-key`、`sf-app-secret`、`sf-api-url` 与开放平台一致；沙箱用沙箱密钥和地址。 |
| **单号不存在/无轨迹** | 确认 SF5122068084664 在顺丰侧有效且与 13262568805 匹配；可先在顺丰官网或公众号用「单号+手机后四位」试查。 |
| **请求 200 但弹窗报错** | F12 → 该请求的 **Response**：看 `isSuccess`、`message`、`traces`；若 `isSuccess: false`，以 `message` 或顺丰错误码排查。 |

---

## 小结（一次配成功清单）

1. 在顺丰开放平台拿到 **partnerID(AppKey)**、**AppSecret**、**API 地址**（沙箱/生产分清）。
2. 在 `application.yml` 里配置 `kuaidi100.sf-app-key`、`sf-app-secret`、`sf-api-url`（及可选 `use-sf-prod`）。
3. 测试订单上**务必填收货人电话**（如 13262568805），发货信息里物流公司选 **顺丰速运**、单号填 **SF5122068084664**。
4. 重启后端，刷新前端，在订单列表点该单号打开「快递物流信息」，确认请求带 `checkPhoneNo=8805` 且返回有轨迹。

按以上顺序做完，顺丰路由查询即可一次配成功。
