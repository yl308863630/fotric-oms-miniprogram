# 本机开发环境挂外网 — 一步步上线

按下面顺序做，即可让其他人通过外网访问你本机正在跑的 OMS。

---

## 第一步：确认本机环境

1. **安装并启动 MySQL**
   - 保证库 `oms_db` 存在（与 `application.yml` 里一致）。
   - 后端启动时会自动建表（`ddl-auto: update`）。

2. **安装 Node.js**
   - 前端需要 Node 18+，用于 `npm run dev`。

---

## 第二步：启动后端

1. 打开终端，进入后端目录：
   ```bash
   cd oms-backend
   ```
2. 启动 Spring Boot（Maven 或 IDE 运行主类均可）：
   ```bash
   mvn spring-boot:run
   ```
   或使用 IDE 运行带 `main` 的 Application。
3. 看到类似 `Started ... Application` 且无报错，说明后端已在 **8080** 端口运行。

---

## 第三步：启动前端

1. 新开一个终端，进入前端目录：
   ```bash
   cd oms-frontend
   ```
2. 首次需要安装依赖：
   ```bash
   npm install
   ```
3. 启动开发服务器：
   ```bash
   npm run dev
   ```
4. 看到类似 `Local: http://localhost:3000` 即可。  
   前端在 **3000** 端口，且已把 `/api` 代理到本机 8080（见 `vite.config.ts`）。

---

## 第四步：本机自测

1. 浏览器打开：`http://localhost:3000`
2. 用你的账号登录（如 sonmin / Sm123456）。
3. 随便点几个功能：销售订单、采购指派、合同、对账单等。
4. 确认没有 404、没有“无法连接”或请求到 localhost:8080 的报错。  
   若有问题，先在本机修好再挂外网。

---

## 第五步：用内网穿透暴露 3000 端口

只暴露**前端端口 3000**，不要暴露 8080。所有接口请求会走「外网域名 → 3000 → Vite 代理 → 8080」。

### 方式 A：ngrok（简单）

1. 安装 [ngrok](https://ngrok.com/download) 并注册（免费即可）。
2. 在终端执行：
   ```bash
   ngrok http 3000
   ```
3. 终端里会显示一行类似：
   ```text
   Forwarding   https://xxxx-xx-xx-xx-xx.ngrok-free.app -> http://localhost:3000
   ```
4. 这个 `https://xxxx....ngrok-free.app` 就是你的**外网地址**，发给别人即可访问。

### 方式 B：Cloudflare Tunnel (cloudflared)

1. 安装 [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-apps/install-and-setup/installation/)。
2. 登录后创建隧道并绑定本地 3000 端口，得到公网域名，用该域名访问即可。

### 方式 C：其他工具

花生壳、frp、路由器端口转发等，只要把「本机 3000」映射到一个公网可访问的地址即可。  
**务必只暴露 3000，不暴露 8080。**

---

## 第六步：外网验证

1. 用**手机 4G** 或**另一台不在你本机的电脑**，在浏览器输入第五步得到的外网地址。
2. 登录，再点：新建订单、指派、合同、对账单、物流等。
3. 若都能正常打开、无报错，说明上线成功。

若出现“无法连接”或接口报错：

- 打开浏览器 **F12 → Network**，看请求的 URL 是否是「外网域名/api/...」。
- 若仍是 `http://localhost:8080/...`，说明还有地方写死了后端地址，需要改成用 `apiBase()` 或相对路径（本项目已改完，一般不会出现）。

---

## 生产/外网环境下如何测试「物流信息是否可查」

在**本机挂外网**或**正式部署**后，按下面方式验证顺丰等物流查询是否正常。

### 1. 在系统界面里测（推荐）

1. 用外网地址或生产地址打开系统（如 `https://xxx.ngrok-free.app` 或正式域名）。
2. **登录**后进入 **销售订单** 列表。
3. 找一条**已填了顺丰单号且收件人手机号完整的订单**，点操作里的 **「物流信息」**。
4. 若弹窗里能展示轨迹节点、无“必传参数不可为空”等报错，说明物流可查。

**注意**：顺丰接口要求收件人手机号后 4 位，订单里必须能带出「收件人电话」；若列表里没有，系统会尝试从订单详情里补全，仍没有则可能报 A1001。

### 2. 直接调接口测（排查用）

- **通过前端域名**（会走代理到后端）  
  浏览器或 Postman 访问（把域名换成你的外网/生产地址）：  
  `https://你的外网域名/api/logistics/query?company=顺丰速运&trackingNumber=SF5122068084664&checkPhoneNo=8805`  
  返回 200 且 JSON 里 `isSuccess: true`、`traces` 有数据即表示可查。
- **仅内网时直连后端**：  
  `http://localhost:8080/api/logistics/query?company=顺丰速运&trackingNumber=单号&checkPhoneNo=手机后4位`  
  同上，看 200 与 `isSuccess`、`traces`。

### 3. 仍报 A1001 / 不可查时

- 确认订单里**收件人手机号**已保存，且传入的 `checkPhoneNo` 为该号码后 4 位。
- 看后端日志里「顺丰API[...] 响应」的报错内容；若是顺丰限流、权限或环境（沙箱/生产）问题，按顺丰侧文档处理。
- 确认 `application.yml` 里顺丰 `partner-id`、`checkword`、`use-prod` 与当前使用的环境一致。

---

## 第七步：安全与注意

- **环境**：当前是开发环境挂外网，数据库、账号等不要和生产混用。
- **关机/休眠**：本机关机或休眠后，隧道会断，别人无法访问；需要时再开本机并重新执行第二步～第五步。
- **长期/正式**：若要 7×24 或正式给客户用，建议把前后端部署到云服务器或内网服务器，而不是长期本机 + 隧道。

---

## 小结

| 步骤 | 做什么 |
|------|--------|
| 1 | 确认 MySQL、Node 已装好 |
| 2 | 启动后端（8080） |
| 3 | 启动前端（3000） |
| 4 | 本机访问 3000 自测通过 |
| 5 | 用 ngrok/cloudflared 等只暴露 3000，得到外网地址 |
| 6 | 用外网地址在手机或别的电脑上登录并点几个功能验证 |
| 7 | 注意安全、关机和长期部署方式 |

按以上顺序做完，其他人就可以通过你提供的外网地址远程访问你本机的 OMS 开发环境。
