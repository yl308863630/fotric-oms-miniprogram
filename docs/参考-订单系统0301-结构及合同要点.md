## 二、0301 合同相关要点

### 1. 合同生成接口

- **ContractController**  
  - `POST /api/contracts/generate-from-order/{salesOrderId}`  
  - 请求体：`{ templateUrl?, partyBRepresentative? }`（仅这两个参数，无 platformName、paymentMethod）  
  - 调用：`contractService.createContractFromSalesOrder(salesOrderId, templateUrl, partyBRepresentative)`

### 2. 合同取值（ContractService.createContractFromSalesOrder）

| 项目 | 0301 取值方式 |
|------|----------------|
| **甲方** partyA / partyAName | 直接 `salesOrder.getOperationEntityTitle()`，无兜底 |
| **乙方** partyB / partyBName | `salesOrder.getDeliveryParty()` |
| 甲方详情（地址/开户行/税号等） | PartnerInfo.findByTitle(operationEntityTitle) |
| 乙方详情 | PartnerInfo.findByTitle(deliveryParty)，**未做 trim** |
| 乙方代表 | 入参 partyBRepresentative 优先；否则取该公司首个 User 的 realName |
| 指派 | 仅当 PartnerInfo 存在且 partyB.getUsername() 非空时：salesOrder.setAssignedUsername(partyB.getUsername()) 并 save |
| 金额 | unitPrice=taxIncludedPrice；totalAmount=deliveryPartyPurchasePrice；amount=**taxIncludedTotal**（与当前项目可能不同） |

### 3. 文档生成（0301）

- 调用：`documentService.generateContractDocument(savedContract, templateUrl)`  
- **无印章**：没有甲方章/乙方章，没有 partyType 参数  
- 生成后：只 setGeneratedUrl、save，无 partyASigned/partyBSigned/待签署 流程  

### 4. 占位符（DocumentService.buildPlaceholders）

- 有：${partyA}, ${partyB}, ${partyAName}, ${partyBName}, ${contractNo}, 产品/金额/日期/银行信息等  
- **无**：${甲方}、${乙方}、${settlementParty}、${partyATitle}、${partyAOrderNo} 等  
- 替换：仅 `replacePlaceholders(document, placeholders)`，无内容控件、无印章插入  

### 5. 订单更新（0301 SalesOrderController）

- **PUT /api/sales-orders/{id}**：入参为 **@RequestBody SalesOrder order**，直接 `order.setId(id); saveOrder(order)`  
- **无**：无 Map 入参、无 syncOrderFromFirstProduct、无 syncOrderFromFirstLogistics  
- 因此前端若传的 order 里 deliveryParty 已设，保存后即为此值，不会被物流子表覆盖  

### 6. 合同下载（0301）

- 仅根据 contract.getGeneratedUrl() 读文件返回，无 protectedImageUrl、无 convertDocxToImage、无 zip

## 三、与当前项目（e:\订单系统）的主要差异

| 维度 | 0301 | 当前项目 |
|------|------|----------|
| 生成合同入参 | templateUrl, partyBRepresentative | 再加 platformName, paymentMethod |
| 甲方来源 | 仅 operationEntityTitle | operationEntityTitle 优先，空则 resolvePartyATitle 兜底 |
| 乙方 PartnerInfo 查询 | findByTitle(deliveryParty) | trim 后查 + findByCompanyTitle 等 |
| 订单 PUT | 直接 SalesOrder，无子表回写 | Map + syncOrderFromFirstProduct/Logistics（已修：顶层 deliveryParty 不被动覆盖） |
| 合同文档 | 仅占位符替换，无章 | 带甲方章/双章、内容控件、replacePlaceholdersWithPartySeal |
| 签署流程 | 无 | 有 partyASigned/partyBSigned、待签署、乙方签署、convertDocxToImage 写 protectedImageUrl |
| 占位符 | 无 ${甲方}/${乙方}/${settlementParty} | 有，且结算方仅工业电商有值 |

若要以 0301 为基准做“合同生成和取值”的严格对齐，可重点对照：甲方/乙方来源、金额字段（amount 用 taxIncludedTotal 还是 deliveryPartyPurchasePrice）、以及生成前订单是否已含最新 deliveryParty（当前项目已保证 PUT 不覆盖顶层交付方）。
