**合同流程说明（指派 → 甲方章 → 乙方签署 → 双章）**：

1. **指派方点击「生成合同」**：在**合作管理 → 合同管理**生成一条合同，并生成**带甲方电子章**的文档（仅 `${partyASeal}` 被替换为甲方章），合同状态为「待签署」。
2. **合同数据传乙方**：乙方在合同管理或销售/采购流程中看到该合同，可下载当前版（仅甲方章）。
3. **乙方签署**：乙方点击签署后，系统重新生成**带双章**的文档（`${partyASeal}`、`${partyBSeal}` 均被替换），合同状态为「已签署」，双方均可下载带双章的合同。

若乙方信息或双章未出现，请查看后端日志：`[ensureContractPartyB]`（乙方从订单回填）、`[buildPlaceholders]`（乙方/结算方为空告警）、`[DocumentService] 已插入甲方章/乙方章`（印章是否插入）。

**合同模板占位符说明**（供 Word 模板校对）：

- **乙方信息**：模板中乙方名称、地址、开户行、帐号、税号、电话请使用 `${partyBName}`、`${partyBAddress}`、`${partyBBank}`、`${partyBAccount}`、`${partyBTaxNo}`、`${partyBPhone}`；也可用 `${乙方}` 表示乙方名称。乙方详细信息的来源为「合作管理 → 用户信息维护」中与交付方（如上海坚领电子科技有限公司）抬头一致的记录，若未维护则仅名称有值。**生成文档前会自动从订单 deliveryParty 回填乙方名称**，若仍为空请查日志。
- **电子章**：模板中须保留 **`${partyASeal}`**、**`${partyBSeal}`**（可在正文或内容控件内），否则不会生成双章。
- **结算方式及期限**：仅**工业电商**（sonmin）侧合同会填入**顶层客户名**（如震坤行）；其他用户合同该占位符会替换为**空字符串**。模板中写 **`${settlementParty}背靠背付款周期`** 即可。


**慢速监督模式**（便于在旁观看操作、排查问题）：不设 `HEADLESS`（或设 `HEADLESS=0`），脚本会**自动启用约 400ms 步进延迟**并打开浏览器窗口，每步操作可见；可自定义延迟：`SLOW_MO_MS=600 node standard-flow-e2e.js`。关键步骤截图仍会保存到当次 `evidence/screenshots/standard-{RUN_ID}/`，便于事后跟进。

**失败清理策略（重要）**：

- 标准 E2E 在流程失败时，不再删除订单数据，而是优先调用订单退回接口（`/api/sales-orders/{id}/return`），将测试单标记为`已退回`并清理指派痕迹。
- 若退回接口因权限等原因失败，脚本会兜底将状态更新为`已退回`。
- 采购管理「销售订单指派」默认列表已排除`已退回`，因此失败测试产生的历史单不会继续干扰下次回归。

2. 确认用户与合作伙伴、合同模板与当前业务一致。
3. 在项目根目录或 `tests` 下执行：
   - `node tests/flow-verification-api.js` 或
   - `node tests/flow-verification-e2e.js`
4. 查看控制台输出与 `evidence/` 下凭证/截图，确认无报错且校验通过即可作为上线前回归依据。
